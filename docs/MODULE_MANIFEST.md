# Faultline — Module Manifest

**Status: frozen after the coverage and dedupe review in `CURRICULUM_REVIEW.md`.**

This is the single source of truth for routing, search, progress, authoring assignments, review assignments, and the build ledger. `src/generated/module-manifest.json` is generated from this file by `npm run validate:manifest`. Do not hand-edit the JSON.

## Reading the table

- **ID** is stable and is the only acceptable authoring assignment.
- **Track / #** place the module in sequence. Prerequisites are guidance, not locks.
- **Purpose** is the production problem the module prepares the learner for.
- **Production question** is shown in the module header.
- **Learning delta** is the one unique takeaway. No two rows may repeat it.
- **Sim mechanic** is what the learner manipulates and watches.
- **Interactivity** lists the controls and decision points.
- **Break condition** is the failure the simulation must make obvious.
- **Case file** is `No` for standard modules, or the incident/company for a case file.
- **Sources** is the research plan, not a claim that the URL was fetched yet.
- **Status** is `planned`, `approved`, `authored`, `reviewed`, or `cut`.
- **D / Min** are difficulty 1–4 and estimated minutes.

Prerequisite IDs must exist. No cycles. The Kubernetes track is authored from the original reserved slot. Illustration values in simulations are labeled in the UI.
